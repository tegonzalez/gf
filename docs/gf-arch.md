# git-folders Architecture

## Purpose

Describe the high-level architecture of the `git-folders` tool and fix the producer-level mechanism contracts — including the work-preservation mechanisms — that the specification, constraints, and verification planning rely on.

## Orientation

`git-folders` is a git-folder repository manager for git. A parent git repository declares git-folders in a tracked manifest (`gf.toml`). Each git-folder is cloned into a user-defined child directory inside the parent workspace. The child is a real git worktree with its own history; its git metadata lives in `.gf/` instead of `.git/`. The child gitdir at `child/.gf/git` is a full, self-contained gitdir with `origin` pointing to the actual git-folder URL.

A binding whose `url` is a plain path to a folder inside a repository maps that subdirectory instead of the whole repository; `gf` finds the repository boundary by URL resolution. Those bindings share a bare repo store per repository under `<root>/.gf` and consume their subdirectory through a sparse linked worktree plus a relative consumer symlink.

`gf` is a POSIX tool. Linux and macOS are supported hosts and behave identically; Windows is not supported. Host adaptation is confined to one module so that no command module carries a host branch.

Every `gf`-owned operation preserves the user's work and usable Git provenance — staged and unstaged changes, untracked and ignored files, local commits and refs, stashes, detached work, and the config and metadata needed to use them. When the identity or ownership of a target is ambiguous, `gf` refuses rather than guesses; purging work is a deliberate user action, never a `gf` mode. Mapping, update, unmapping, remapping, worktree, and inspection operations are all bound by this.

## Design Goals

- One producer per git operation, serving both binding forms (`GF-D15`): a fix or a witness reaches every consumer of the operation.
- Preservation before convenience: an operation that cannot complete without endangering work refuses and reports, instead of offering a flag that destroys.
- Identity from recorded evidence: path presence, spelling, or link shape is never proof of ownership.
- Clean ownership boundaries: `manifest.py` owns `gf.toml`, `layout.py` owns `.gf` spelling, `shelf.py` owns git mechanism, `platform.py` owns host differences, `backends.py` owns process environment.

## Module Inventory

### Modules and responsibilities

### `src/gf/platform.py`

The host adaptation layer. It owns four primitives:

- `logical_cwd()` — the working directory, preferring the `PWD` spelling when `PWD` is absolute and names the same directory as the process working directory. Moved here from `cli.py`, which now calls this module. Spelling is preserved; a command inside a `worktree add` symlink still targets the source child.
- `same_path(a, b)` — path comparison by directory identity, so a symlinked spelling and its target compare equal. When either path does not exist, comparison falls back to resolved spelling so a local placeholder URL can be skipped before the child exists.
- `exec_or_run(...)` — process replacement for the `exec` mode of the shared runner. `runner.py` keeps `capture` and `stream` and delegates only replacement here.
- `acquire_lock(path)` *(new)* — opens the lock file (creating it when absent) and takes a blocking `flock(2)` on it, returning the held descriptor. The caller holds the descriptor for the command's lifetime; the kernel releases the lock on exit or kill, so a crashed process never welds a lock file.

Its inputs are the process environment and the filesystem; its outputs are a path, a comparison result, a replaced process, and a held lock. It wraps the host, not git: it never invokes `git`, reads `gf.toml`, or interprets the `.gf` layout, so `GitCliBackend` remains the sole git owner and `manifest.py` the sole manifest owner. It does not probe interpreter ABI.

### `src/gf/cli.py`

The command-line entry point and parser. It implements the global `-C <path>` option (only when it appears before the subcommand), `--version` / `-v`, command dispatch, the project-root discovery protocol, and the mutation lock:

- `main` — parses and dispatches; for a mutating command (`clone`, `init`, `pull`, `rm`, `worktree add`, `worktree remove`) it acquires the parent repository's lock before dispatch, so every planning read and shared write inside the command runs serialized.
- `_acquire_parent_lock` *(new)* — resolves the parent context (`resolve_context`), derives the common gitdir (`git rev-parse --git-common-dir`), and holds `platform.acquire_lock(<common dir>/gf.lock)` for the command; an unresolvable common dir or an acquisition failure refuses the command naming the contended resource. Read commands (`status`, `ls`, `worktree list`) and passthroughs (`sh`, `git`, `diff`, `log`) take no lock.
- `_resolve(cwd)` — central manifest/parent discovery.
- `_align_columns(rows)` — generic column alignment for `ls` and `status`.
- `_normalize_url(url)` / `_name_from_url(url)` — URL shorthand expansion and basename name derivation.
- `_get_version()` — package version from `importlib.metadata` with a `pyproject.toml` fallback.
- `_apply_chdir(argv)` — applies leading global `-C <path>` options and returns the remaining argv; trailing `-C` is left for git passthrough commands.
- `cmd_clone` — supports `--depth <n>` and `--single-branch`.
- `cmd_pull` — supports `--rebase` and `--autostash`. There is no `--force`: no flag waives preservation.
- `cmd_status` — supports `--remote` drift classification; local-only either way.
- `cmd_ls`, `cmd_rm` (with `--all`), `cmd_init` (with `-n <name>` and `--url <url>`).
- `cmd_diff`, `cmd_log`, `cmd_git` — passthrough commands that forward trailing `argparse.REMAINDER` args to git, with explicit reconstruction to preserve token order.
- `cmd_worktree_add`, `cmd_worktree_list`, `cmd_worktree_remove` — `-f` on `worktree add` replaces a conflicting link or file at a child path but never a real directory, and is unrelated to the removed `pull --force`.
- `cmd_sh` — runs a shell or command with `GIT_DIR` set to the child gitdir.

Working-directory resolution, path comparison, and the lock primitive come from `platform.py`. `cli.py` contains no host or interpreter test of its own.

### `src/gf/layout.py`

The checkout resolver: the single owner of the `.gf` physical layout for both binding forms. It maps a binding to its `gitdir`, `work_tree`, `common_dir`, `subdir`, and state path — `child/.gf/git` for a whole-repo binding; `<root>/.gf/repos/<repo-key>/git` plus the `<root>/.gf/wt/<repo-key>/<checkout-key>` worktree for a subfolder binding. It derives `repo-key` and `checkout-key`, resolves an existing binding's checkout from its consumer link's realpath, and is filesystem-only: it performs no git calls, which keeps it callable from discovery and selection code that must not touch git. All `".gf"`-layout literals live here.

Its predicates — `in_gf_tree`, `in_git_tree`, `in_gf_wt`, `owns_consumer_link`, `owning_root`, `storage_is_real`, `whole_repo_gitdir_is_real` — locate and bound storage; they are the containment evidence half of the identity contract. Locators are never identity proof by themselves: what a path *is* comes from `layout`, whether it is *this binding's* comes from the recorded state and store verification in `shelf.py`.

### `src/gf/shelf.py`

The git operations layer and the owner of every preservation mechanism. Its seams group by duty:

- Child gitdir and URL resolution — `_init_child_gitdir`, `init_git_folder`, `resolve_repo_url`, `_resolve_local_url`, `_resolve_remote_url`, `_resolved_git_url`, `_is_git_folder_child`, `_set_child_origin`, `resolve_ref`, `_resolve_remote_branch`, `_effective_branch`, `is_branch`, `_remote_default_branch`, `_upstream_has_branch`, `_upstream_has_tag`, `_store_default_branch`, `_store_has_branch`, `_binding_branch`, `_ensure_origin_head`.
- Store coverage — `ensure_repo_store`, `_ensure_branch_coverage`, `_ensure_pinned_ref`, `_fetch_store`, `_assert_store_origin`, `_assert_safe_refspecs` *(new: refuses a pre-existing `remote.origin.fetch` line whose `+` destination lands outside `refs/remotes/origin/`)*, `_live_refspec_lines`, `_branch_refspec`.
- Integration — `_apply_ref`, `_fetch_and_checkout`, `_fetch_and_rebase`, `_retention_ref` *(new: records the outgoing `HEAD` under the checkout's `refs/worktree/gf-retained` before a transition that could orphan it)*. `_apply_ref` is the single ref-application operation both pull flows share; under the preservation contract it attaches or creates the local tracking branch and integrates fast-forward-only, detaches at a pinned SHA, rebases only on explicit `--rebase`, and knows neither `-B` nor `-f`.
- Checkout and link lifecycle — `ensure_checkout`, `ensure_consumer_link`, `_place_consumer_link`, `rollback_consumer_link`, `ensure_shared_binding`, `strip_placeholder_child`, `_vacate_checkout`, `_siblings_served`, `pull_shared_bindings`, `_checkout_record_valid`, `_checkout_record_dir`, `_sparse_union`, `_lock_worktree`, `_save_checkout_state`, `_remove_checkout`, `_remove_repo_store`, `_cleanup_new_child`.
- Unmap and conversion — `remove_child`, `_convert_whole_repo_gitdir` *(new: the `.gf/git` → `.git` move and selective `.gf` teardown arm)*, `_rewrite_linked_gitfiles` *(new: reconcile and rewrite registered linked-worktree gitfiles across the move)*.
- Inspection — `drift`, `binding_scope`, `scoped_porcelain`, `_resolve_effective_sha_local`, `recorded_url`, `recorded_binding_url`, `recorded_url_matches`.
- Parent worktrees — `list_parent_worktrees`, `linked_git_folders_in_worktree`, `linked_git_folder_symlinks_in_worktree`, `unlink_linked_git_folders_in_worktree`, `is_linked_child`.
- Selection — `select_children` and its path-matching helpers.

`update_child` / `init_child` are the whole-repo entry points; `pull_shared_bindings` is the grouped subfolder flow. Rollback helpers remove only artifacts their invocation provably created.

### `src/gf/manifest.py`

Manifest reading, writing, and discovery. Resolves the parent repo context, reads `gf.toml`, `gf.local.toml` overrides, and computes the effective URL/ref for each git-folder. `write_manifest` replaces `gf.toml` atomically through a temporary file, so an interrupted write never leaves a half-written manifest. It does not interpret the URL; URL resolution belongs to `shelf.py` because it may call git.

### `src/gf/state.py`

Per-checkout metadata records. A whole-repo child's record lives at `child/.gf/state`; a store checkout's at `<root>/.gf/wt/<repo-key>/.<checkout-key>.state`. Fields: `resolved` (SHA), `ref`, `url` (effective URL spelling), `override`, `bindings` (served subdirs), `binding_urls` (consumer path → effective URL resolution). Records merge on write and are written atomically; they persist through unmap so a re-add can identify retained work. Field growth must stay absent-tolerant — a record from any earlier admitted shape reads cleanly.

### `src/gf/backends.py`

- `GitBackend` protocol for spawning or mocking git.
- `GitCliBackend` — default real git backend. `clean_environ` scrubs ambient `GIT_*` variables; every managed-gitdir call injects `core.hooksPath=/dev/null` so a hook delivered through committed content or a rewritten store config cannot execute during `gf`-owned operations.

### `src/gf/runner.py`

- Shared command runner with three modes: `capture`, `stream`, and `exec`.
- `capture` collects output for parsing.
- `stream` echoes stdout/stderr live while collecting it for error messages.
- `exec` replaces the process when stdout is a terminal so interactive programs (e.g. pagers) work. It delegates the replacement itself to `platform.py`; `runner.py` owns mode selection and the `capture` and `stream` implementations.

### `bin/gf`

The development launcher. If `.venv/bin/python` exists it re-execs that interpreter; if not, it continues under the current interpreter with `src/` prepended to `sys.path`. It carries no host test and no ABI probe. A developer must remove a virtual environment left from another host and recreate it with `uv sync`. The installed console script does not use this launcher.

### `tests/conftest.py`

The test-environment seam. It owns fixture isolation and the host inputs the suite must not inherit: hermetic git identity plus `init.defaultBranch = master` through a `HOME`-redirected `.gitconfig` — a channel `clean_environ` cannot close — with `GIT_CONFIG_NOSYSTEM` kept passing through. The pin controls real Git without wrapping it or changing product behavior.

### `tests/mock_git.py`

In-memory mock git backend used by `test_cli_permutations.py`. It simulates `init`, `remote add/set-url`, `remote set-head`, `fetch`, `checkout`, `merge --ff-only`, `rev-parse`, `show-ref`, `symbolic-ref`, `status --porcelain`, and `config` commands against a `pyfakefs` filesystem. It models the initial branch as `master`, matching the real-Git pin. As the preservation contracts are admitted, the mock tracks the rewritten producer contracts rather than freezing baseline behavior.

## Architecture

### Data flow

```text
parent repo
├── gf.toml            # canonical manifest
├── gf.local.toml      # untracked local overrides
├── .git/gf.lock       # mutation lock (flock, fd-held)
├── <child>/               # whole-repo binding
│   ├── .gf/git/       # child gitdir
│   │   ├── HEAD
│   │   ├── objects/       # self-contained object store
│   │   ├── refs/
│   │   └── config         # origin = actual git-folder URL
│   ├── .gf/state      # resolved ref metadata
│   └── ...                # git-folder worktree
├── .gf/                   # subfolder-binding storage at the parent root
│   ├── repos/<repo-key>/git/          # bare repo store: objects, refs, origin
│   └── wt/<repo-key>/<checkout-key>/  # sparse linked worktree + .<checkout-key>.state
└── <subfolder path>       # consumer link → .gf/wt/<repo-key>/<checkout-key>/<subdir>
```

Records that carry preservation weight: each store's `<store>/worktrees/<checkout-key>/` worktree record (`gitdir`, `commondir`, `locked`) names and protects its checkout; each checkout's `refs/worktree/gf-retained` holds its outgoing `HEAD`; each `.state` file records the binding identity. None of these is deleted except under the ownership rules of `GF-D22`.

### Update flow — whole-repo child

`cmd_pull` selects bindings under the held lock; `update_child` runs per whole-repo child:

1. Effective `url`/`ref` from the manifest and overrides; the recorded resolution satisfies an unchanged `url` (`recorded_url_matches`), else `resolve_repo_url` resolves it — identity before any mutation.
2. Occupancy and storage gates: an existing non-git-folder path refuses; a `.gf` anchor resolving through a link refuses (`whole_repo_gitdir_is_real`).
3. Create arm — a child path that is absent or lacks `.gf/git`: `mkdir`, `_init_child_gitdir`, `_set_child_origin`, the initial fetch and ref application through `_fetch_and_checkout` (a fresh gitdir has no user refs, so applying the ref is creation, never a reset), then the state record and the `.gitignore` recommendation. Any failure rolls back through `_cleanup_new_child`, which removes only what this invocation provably created.
4. Unscoped `status --porcelain` dirty check on an established child: dirty refuses (exit 3) unless `--autostash` runs `stash push -u -m "gf autostash"` first.
5. `_set_child_origin` reconciles `origin` to the actual effective URL — a failure after a taken stash still restores it. Coverage: `_ensure_pinned_ref` probes `ls-remote` for a needed tag and appends its non-forced line, or `fetch --no-tags origin <sha>` for a commit; `_assert_safe_refspecs` refuses a legacy `+` line into user refs. Then `fetch --no-tags origin` on `common_dir`.
6. `_apply_ref`: `_retention_ref` records the outgoing `HEAD`; a branch binding attaches to or creates the local tracking branch (`checkout <branch>` / `checkout -b <branch> origin/<branch>`) and runs `merge --ff-only origin/<branch>` — an existing branch is never reset or recreated, and divergence refuses reporting the truthful ahead/behind state; a tag or commit detaches at `checkout <sha>`; `--rebase` runs `git rebase origin/<branch>` instead of the merge.
7. `--autostash` restores with `stash pop --index` after success and after every post-stash failure — the index partition is part of the preserved work; a failed pop leaves the named stash entry and reports manual recovery.
8. `save_checkout` merges the record (`resolved`, `ref`, `url`, `override`); a freshly initialized child prints the `.gitignore` recommendation.

### Update flow — subfolder bindings

`pull_shared_bindings` groups the selected bindings so shared storage is touched once:

1. Each binding's repo URL and subdir come from its recorded resolution or a fresh `resolve_repo_url`; a changed `url` resolving to a whole repository refuses every selected binding before anything changes.
2. Per repo store: `ensure_repo_store` creates a missing store (`init --bare`, `remote.origin.url`, first refspec line); `_assert_store_origin` keys the store to the recorded repo URL; `_assert_safe_refspecs` refuses forced legacy lines; `_ensure_branch_coverage`/`_ensure_pinned_ref` append missing coverage; then exactly one `fetch --filter=blob:none --no-tags origin` per store (full-fetch fallback with warning), plus `fetch --no-tags origin <sha>` for a pinned commit the store lacks.
3. Per checkout key: `ensure_checkout` — create via `worktree add --no-checkout --detach` only when the record proves absence (a fresh checkout materializes at the resolved ref through the same `_apply_ref` contract), verify the record at `<store>/worktrees/<checkout-key>`, refuse a checkout directory lacking its record rather than rebuild over it, widen the sparse cone to the union of served subdirs, remove its `.git` gitfile, and lock the worktree. A binding that joins an existing checkout re-links only: the cone widens to materialize its subdir, and its `HEAD` and index are untouched.
4. One unscoped dirty check per materialized checkout; the same refusal/`--autostash` contract applies to the whole checkout, and a dirty shared checkout blocks every binding it serves.
5. Apply the ref once per checkout through `_apply_ref`, under the same contract as a whole-repo child — attach or create the tracking branch, fast-forward-only integration, divergence refusal, `--rebase` as the explicit rebase, detached SHA for tag/commit, and the durable-reachability rule.
6. `ensure_consumer_link` creates or retargets the relative link, refusing when it would not sit lexically under the owning root or would land inside `.gf`/`.git`; `_save_checkout_state` merges `bindings`/`binding_urls`; `_vacate_checkout` prunes only provably-dead record entries, from the owning root's manifest; one `Pulled <name>` line prints per served binding with `(moved with …)` markers.

### Identity and reconnection

A binding reconnects through evidence, never through a path spelling alone. The chain, each link owned in `shelf.py`/`state.py`:

- The manifest `path` is validated lexical containment; `binding_root`/`owning_root` prove which parent's storage a consumer path belongs to before any write.
- The checkout's `.state` carries `binding_urls` (consumer path → effective URL) and `url`; a matching record identifies the binding's repository without re-resolving.
- The `repo_key` derives the store path from the recorded repo URL; `_assert_store_origin` verifies the store's own `remote.origin.url` against it before writes or fetches.
- The `checkout_key` selects the checkout; `_checkout_record_valid`/`_checkout_record_dir` verify the worktree record names that checkout.

A re-add rejoins the retained store and checkout — `HEAD`, index, stashes, and dirty state intact — only when the effective URL selects the recorded store and the effective ref selects the original checkout key. If `latest` now resolves to another default branch, it selects another key; specify the original resolved branch to reconnect to the retained checkout. The operation never resets `HEAD` or discards the index. Where the evidence cannot identify retained work unambiguously — a mismatched origin, a forged anchor, an occupied path with no record — it refuses and reports what exists. A dangling link, missing checkout, or missing `.gf` anchor degrades the binding to `missing` in inspection and to a re-materialization-or-refusal on pull; it never erases the record.

### Mapping lifetime and unmap

Subfolder `gf rm` (`remove_child`, `owns_consumer_link` gate) removes only the consumer link and the manifest declaration; the repo store, the shared checkout — work tree, index, stash — and the state record persist.

Whole-repo `gf rm` converts instead of deleting (`_convert_whole_repo_gitdir`):

1. Verify the target: the child is a genuine whole-repo child, `whole_repo_gitdir_is_real` holds, and `child/.git` is absent — a `.git` already present refuses.
2. Reconcile registered linked worktrees before the move (`_rewrite_linked_gitfiles`): for every `<gitdir>/worktrees/<n>` record, read the record's `gitdir` file to find the external `.git` gitfile; a gitfile that exists must be writable and currently name the old `.../.gf/git/worktrees/<n>` path, or the command refuses before the move; an absent gitfile marks a stale record that needs no rewrite.
3. Move `child/.gf/git` to `child/.git` — `core.worktree` is absolute and keeps working, and `HEAD`, index, refs, config, and `origin` stay intact.
4. Rewrite each reconciled gitfile to the new `.../.git/worktrees/<n>` path; a record's `commondir` is relative and survives untouched. A post-move write failure reports the exact unresolved path — `git worktree repair` remains the documented recovery — rather than claiming completion.
5. Remove provably gf-owned `.gf` content (`state`); remove `.gf` itself only when left empty; foreign content stays and is reported.
6. `write_manifest` atomically replaces `gf.toml` only after every selected child is converted or unlinked.

Re-adding reconnects by the identity chain above only when the effective `url` selects the same recorded repo store and the effective ref selects the original checkout key; same URL alone is insufficient if the selected ref resolves to another checkout. A consumer path already carrying a `.git` repository is refused as occupied: a plain repository is not provably the binding's retained work, and `gf` does not adopt it.

### Serialization and locking

`cli._acquire_parent_lock` resolves the parent repository's common gitdir — `git rev-parse --git-common-dir` at the resolved root — and `platform.acquire_lock` takes a blocking `flock` on `<common dir>/gf.lock`. Mutating commands (`clone`, `init`, `pull`, `rm`, `worktree add`, `worktree remove`) hold it exclusively from before the first planning read through command end; the descriptor is the lock, so a kill or crash releases it with no stale file to break. Read-only commands and passthroughs take no lock. One lock per parent repository covers every worktree of that parent — including a pull that mutates storage under a binding's owning root — and closes the last-writer-wins window recorded as `GF-TRB-11`. A command that cannot resolve the common dir or cannot acquire refuses, naming the contended resource.

### Interruption and recovery

Partial effects are retained, not swept. `write_manifest` and `save_checkout` replace atomically, so readers see the old or new record, never a torn one. A command killed mid-operation leaves its artifacts inspectable: the next run classifies what it finds through the same identity and `missing` rules, git's own in-progress merge/rebase markers refuse a stacked operation, and a stranded `gf autostash` entry stays named in the checkout's stash list. Error envelopes carry the partial effect — bindings already served, `e.lines`, `e.folder` — and the recovery path.

Deletion at rollback or recovery requires proof this invocation created the artifact: `_cleanup_new_child` removes only a child/gitdir the failing create arm provably started; `ensure_checkout` removes a checkout only under its `created` flag; `_remove_repo_store` runs only for a store this invocation created and never for a pre-existing or still-serving one; `rollback_consumer_link` removes only the link the failed call placed; `strip_placeholder_child` removes only a verified empty placeholder; `cmd_worktree_add` removes only the worktree it just registered, verified by the record. Anything pre-existing, foreign, or uncertain is retained and reported.

## Design Decisions

### Seams and contracts

1. **Manifest contract** — `gf.toml` is the single source of truth; `gf.local.toml` may override `url` and `ref` by git-folder `name`. Owner: `src/gf/manifest.py`; the direction is one-way — command modules consume the effective `url`/`ref` through it and never parse the manifest themselves; its test seam is `tests/test_edge_cases.py` (override cases) and `tests/test_state.py` (the recorded override).
1. **Gitdir contract** — a whole-repo child's `.gf/git` is a full gitdir, not bare; all objects and refs live in the child. Owner: `src/gf/shelf.py` (`_init_child_gitdir` creates it; `src/gf/layout.py` spells the path); its test seam is `tests/test_clone_and_pull.py`.
1. **Layout contract** — `src/gf/layout.py` is the only module that spells `.gf` layout paths; every consumer of `gitdir`, `work_tree`, `common_dir`, `subdir`, or state paths goes through the checkout resolver, and the resolver makes no git calls. Its test seam is `tests/test_layout.py`.
1. **Checkout-polymorphism contract** — every git operation exists once and works on the `Checkout` the resolver returns: plumbing operations (fetch, refspec config, `remote set-head`, `ls-remote`, store-level ref resolution) and `worktree add`/`lock` address `common_dir`, and worktree operations (checkout and branch attach, `merge --ff-only`, rebase, stash, status, `rev-parse HEAD`, sparse checkout) address `gitdir` and `work_tree`. A git call whose operands are worktree-relative must pin the subprocess `cwd` to `work_tree`, or the operands resolve against the caller's process cwd instead. `src/gf/layout.py` owns the derivation of a binding's `Checkout` (`whole_repo_checkout`, `subfolder_checkout`, `resolve_checkout`) and its one form property, `Checkout.is_store_checkout`; consumers read fields and that property and never re-derive the form. The places where the two forms may differ are fixed by `GF-D15`. Review witnesses, run at every review of `src/gf/`: `grep -rn 'def .*subfolder\|_at(' src/gf/` shows no twin operation (the resolver's `subfolder_checkout` constructor is its expected match), and `grep -rn '"\.gf"' src/gf/` matches only `src/gf/layout.py`. Its test seam is `tests/test_checkout_replumb.py` and `tests/test_layout.py`.
1. **Store and checkout contract** — one bare repo store per normalized repo URL under `<root>/.gf/repos/<repo-key>/git` whose fetch refspec lines are only ever appended, never rewritten or removed — a pre-existing `+` line landing outside `refs/remotes/origin/*` is unsafe legacy state and refuses (`GF-D17`); one sparse linked worktree per `(store, checkout key)` under `<root>/.gf/wt`, addressed only through `GIT_DIR`/`GIT_WORK_TREE`, its `.git` gitfile removed and the checkout locked; each consumer path holds a relative symlink into the checkout's mapped subdir, owned by the parent root whose `.gf/wt` contains its realpath. Owner: `src/gf/shelf.py` for creation and `src/gf/layout.py` for the keys and paths; the direction is one-way — consumers see only the relative link and never address `.gf` directly; its test seam is `tests/test_store_checkout.py` and `tests/test_checkout_key.py`.
1. **URL resolution contract** — a `url` is a plain path; resolution runs only in `clone` and `pull`, and its result is recorded so `status`, `ls`, and passthrough commands stay local-only. Owner: `src/gf/shelf.py`; the direction is one-way — `status`, `ls`, and the passthrough commands read the recorded result rather than resolving; its test seam is `tests/test_url_resolution.py`.
1. **Origin contract** — child `origin` fetches from and pushes to the actual git-folder URL. Owner: `src/gf/shelf.py` (`_set_child_origin`); its test seam is `tests/test_clone_and_pull.py` and the recorded `remote.origin.url` pins in `tests/test_subfolder.py`.
1. **Ref contract** — `latest` resolves to the remote default branch; branch refs use their local tracking branch and integrate `origin/<branch>` fast-forward-only by default, with rebase only on the user's explicit request and durable retention of original history. Branches are never reset or recreated; tag/commit refs resolve to a SHA and detach. Owner: `src/gf/shelf.py` (`resolve_ref`, `_apply_ref`); its test seam is `tests/test_clone_and_pull.py`, `tests/test_clone_subfolder.py`, and `tests/test_checkout_key.py` (ref → key).
1. **Discovery contract** — `_resolve(cwd)` walks up from `cwd` to find the parent `.git` and `gf.toml`. Owner: `src/gf/cli.py`; the direction is one-way — every command resolves its context through it; its test seam is `tests/test_realpath_discovery.py`.
1. **Platform contract** — `platform.py` owns path identity, process replacement, and the advisory lock, and the direction is one-way: command and backend modules consume the primitives, and none of them reads host identity. Its unit seam is `tests/test_platform.py`; runner failure translation remains owned by `tests/test_runner.py`.
1. **Host contract** — Linux and macOS are supported and produce identical command behavior. Windows is a declared gap, not an unstated one: `gf` carries no Windows process-creation path and no `Scripts/python.exe` lookup. Owner: `src/gf/platform.py`; the direction is one-way — the supported hosts share the one implementation and an unsupported host gets no code path; its check is the per-host control, `uv run pytest -x` with a virtual environment created on each host.
1. **Test-environment contract** — `tests/conftest.py` pins the real-Git initial branch to `master`, `tests/test_host_inputs.py` proves the pin through `git init`, and `tests/test_runner.py` invokes `sys.executable` instead of a host-resolved `python`. The control is `uv run pytest -x` on each supported host with a virtual environment created on that host.
1. **Preservation contract** — every `gf`-owned operation preserves the spec's protected-work set and refuses on ambiguous ownership or identity; no flag or mode waives it. Owner: `src/gf/shelf.py` for the mechanism, `src/gf/cli.py` for the flag surface; the direction is one-way — every mutation path preserves or refuses; its witness families are named in `docs/gf-testing.md`.
1. **Identity contract** — a binding reconnects only through recorded evidence: the checkout's `binding_urls`/`url` record, the `repo_key`-derived store path, the store's `remote.origin.url`, the checkout key, and the worktree record. Owner: `src/gf/shelf.py` verification seams with `src/gf/state.py` holding the records and `src/gf/layout.py` the paths; path presence is never identity. Its test seam is `tests/test_state.py` and `tests/test_subfolder.py`.
1. **Locking contract** — mutating commands hold `flock` on the parent repository's `<git common dir>/gf.lock` for their whole run; read commands and passthroughs take none, and a held descriptor means a crash welds nothing. Owner: `src/gf/platform.py` (`acquire_lock`), acquired by `src/gf/cli.py` (`_acquire_parent_lock`); one lock domain per parent repository, covering every worktree.
1. **Recovery contract** — rollback and recovery delete only artifacts the failing invocation provably created; interruption leaves retained, truthfully reported state, and no next-start cleanup guesses at ownership. Owner: `src/gf/shelf.py` rollback helpers and `src/gf/cli.py`'s `worktree add` removal; retention is the default and deletion requires proof.

## Policy And Authority Boundaries

This document owns the module inventory, seam ownership, mechanism decisions, and the decision register. Operative command behavior, flags, exit codes, and error envelopes live in [gf-spec.md](gf-spec.md); prohibition rules and their detection signals live in [gf-constraints.md](gf-constraints.md); witness selection and the assurance mapping live in [gf-testing.md](gf-testing.md); user-facing diagnostics live in [gf-troubleshooting.md](gf-troubleshooting.md). The consumed contracts — manifest grammar, URL resolution, fetch refspecs, update and drift algorithms, target selection — are cited from the specification's named sections, not duplicated here.

Known cross-owner deltas, each with its owning document (none re-opens the settled contract):

- The baseline producers lag this contract: `src/gf/shelf.py::_apply_ref` still issues `checkout -B` and honors `force`; `_ensure_pinned_ref` still appends `+refs/tags/<ref>:refs/tags/<ref>`; `cmd_pull` still accepts `--force`; `update_child` swallows a failed `stash pop` on the update-failure path instead of reporting the retained stash; `remove_child` still removes `child/.gf` recursively without linked-worktree reconciliation. These are implementation baselines superseded by `GF-D16`, `GF-D17`, `GF-D19`, and `GF-D21` — under the refusal-first posture, an unsafe transition refuses until its replacement is admitted rather than executing the legacy path.
- Baseline stores and child gitdirs written by the old `_ensure_pinned_ref` may carry a `+refs/tags/*` line. Spec and constraints forbid both rewriting coverage lines and moving user refs, which reconciles to one behavior: `_assert_safe_refspecs` refuses the operation until the user repairs the line with their own `git config` — a deliberate user action, not a `gf` mode.

## Constraints References

The binding constraints live in [gf-constraints.md](gf-constraints.md); the load-bearing ones for this architecture are: *Do not implicitly discard or overwrite user work*, *Do not force-move a user-owned ref*, *Do not mutate a repository other than the verified binding target*, *Do not erase a binding's identity when its links are missing*, *Do not rewrite or remove fetch refspec lines on a shared repo store*, *Do not create a second checkout of one branch in one repo store*, *Do not leave a `.git` gitfile in a `gf` checkout*, *Do not duplicate a git operation per binding form*, *Do not construct `.gf` layout paths outside the checkout resolver*, *Do not wrap git, the manifest, or the `.gf` layout in the platform module*, *Do not place git-folder storage outside the parent worktree*, *Do not fetch the network in `ls` or `status`*, *Do not branch on the host platform in command logic*, and *Do not let `gf` become a second committer*.

## Failure Modes

| Failure mode                             | Detection                                                        | Mechanism                                                                | Resulting state                                                                 |
| ---------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Dirty checkout at pull                   | Unscoped `status --porcelain` on the checkout                    | Refuse unless `--autostash`; autostash does `stash push -u` then `pop --index` | Work preserved in place or in a named `gf autostash` entry                      |
| Diverged local branch                    | `merge --ff-only` failure with ahead/behind counts               | Refuse; `--rebase` is the explicit path                                  | Nothing moved; retention ref holds the outgoing HEAD                            |
| Rebase conflict                          | Rebase exit and in-progress markers                              | Leave the in-progress rebase; report resolve-or-abort                    | `git rebase --abort` recovers; retention ref and ORIG_HEAD intact               |
| Pop conflict after autostash             | `stash pop --index` failure                                      | Keep the stash, surface the conflict                                     | Named stash entry retained with recovery instruction                            |
| Store origin mismatch                    | `_assert_store_origin` before writes or fetch                    | Refuse                                                                   | No refspec write or fetch runs against the wrong store                          |
| Forced coverage into user refs           | `_assert_safe_refspecs` reads `remote.origin.fetch` lines        | Refuse before any fetch; name the repair                                 | Unsafe legacy line never executes                                               |
| Checkout dir without record              | `_checkout_record_valid` false on occupied path                  | Refuse — never rebuild over existing files                               | Foreign files untouched                                                         |
| Consumer link not owned                  | `owns_consumer_link` realpath into `.gf/wt`                      | Refuse `rm`; report the owning worktree                                  | Link and storage untouched                                                      |
| Concurrent gf writers                    | `flock` on `<common dir>/gf.lock`                                | Serialize mutating commands; acquisition failure refuses                 | One writer at a time; no torn manifest/store/state                              |
| Killed mid-operation                     | Next run sees partial artifacts and in-progress markers          | Retain; report partial effects; refuse ambiguous identity                | Recoverable state; no welded lock (fd-held)                                     |
| `.gf` or gitdir swapped for a link       | `storage_is_real`/`whole_repo_gitdir_is_real`                    | Refuse before any write through the link                                 | Donor storage never modified                                                    |
| Foreign content under `.gf` at rm        | Directory listing after `git`/`state` removal                    | Retain the remainder and report it                                       | Ordinary `.git` works; `.gf` left in place                                      |
| Linked-worktree gitfile not reconcilable | Preflight pass over `worktrees/*/gitdir` targets before the move | Refuse before the move; a post-move write failure reports the exact path | Binding stays gf-managed on refusal; `git worktree repair` recovers a straggler |
| Upstream tag moved                       | Non-forced tag line rejects the fetch                            | Surface the rejection as divergence                                      | Local tag preserved                                                             |
| Unborn or missing HEAD                   | `rev-parse HEAD` miss, absent gitdir/link                        | Degrade to the documented missing/unborn class                           | Truthful report; no probe, no creation                                          |
| In-progress merge/rebase on next pull    | git's own in-operation refusal                                   | Surface the error; refuse until resolved or aborted                      | No stacked operations on a mid-state                                            |

## Acceptance Criteria

Each phase admits by one atomic cutover condition — old and new producers, permitted coexistence, ordering, surviving authority, and preservation/recovery verification bound to that phase's baseline and observers. `P1` refuses an unimplemented unsafe transition rather than exposing the destructive legacy path while `P2`/`P3` are pending; no phase is a release.

### P1 — safe refusals, verified identity, protected fetch refs, history-preserving integration/inspection

| Field | Gate |
| ----- | ---- |
| Phase baseline | Current `src/gf/` producers with the amended spec and constraints admitted: `_apply_ref` (`checkout -B`/`-f`), `_ensure_pinned_ref` (`+refs/tags/` line), `cmd_pull` `--force`, the four-class `drift`. |
| Old producer/selector | `shelf._apply_ref`'s `checkout -B`/`-f` arms; `shelf._ensure_pinned_ref`'s forced tag line; `cmd_pull`'s `--force`; `update_child`'s silent pop-failure swallow; `drift`'s dirty-only classification. |
| New producer/selector | The same producers re-scoped in place: `_apply_ref` attach-or-create plus `merge --ff-only`/`rebase`/detached SHA; `_retention_ref`; `_assert_safe_refspecs`; `_ensure_pinned_ref` non-forced coverage; `--no-tags` fetches; the full autostash contract; `drift`'s history classes. |
| Permitted coexistence | None — no flag day and no twin operations (`GF-D15`). `--force` is removed, not deprecated; an unsafe transition refuses until the rewrite is admitted. |
| Prerequisite and switch ordering | Spec/constraints amendments admitted → this revision admitted → producers rewritten in place under the same names → witnesses rewritten to the new contract → cutover verified. |
| Authority surviving the switch | `GF-D5`–`GF-D9`, `GF-D11`, `GF-D14`, `GF-D15` (layout, manifest, URL resolution, keys); the recorded state schema (`resolved`, `ref`, `url`, `override`, `bindings`, `binding_urls`) is unchanged. |
| Preservation/recovery verification | Witnesses prove ahead/diverged/dirty/pinned/moved-tag cases preserve work; autostash restores on success and failure; an interrupted pull leaves retained, truthfully reported state. |
| Affected observers | `tests/` pull, clone, status, and refspec families; `tests/mock_git.py`; the stale troubleshooting entries its owner corrects. |

### P2 — retained mapping lifetime, whole/subfolder unmap and remap, linked-worktree provenance

| Field | Gate |
| ----- | ---- |
| Phase baseline | The P1-admitted tree. |
| Old producer/selector | `remove_child`'s recursive `.gf` removal without worktree reconciliation; any join path that resets a retained checkout; missing-linkage paths that rebuild or drop identity. |
| New producer/selector | `_convert_whole_repo_gitdir`, `_rewrite_linked_gitfiles`, and selective `.gf` teardown inside the same `remove_child`/`cmd_rm` seam; `ensure_checkout`/`ensure_shared_binding` re-link-only joins; `missing` degradation with identity re-materialization. |
| Permitted coexistence | A converted `.git` child coexists with gf-managed children indefinitely — it is an ordinary repository, not a second authority. |
| Prerequisite and switch ordering | Follows P1 so integration refusals are already safe; the state schema is unchanged and P1-era records remain readable (absent-tolerant loads). |
| Authority surviving the switch | `GF-D9`/`GF-D14` link removal and link ownership; the specification's `gf rm` contract; all P1 mechanism. |
| Preservation/recovery verification | Witnesses prove `rm` leaves a usable `.git` (`HEAD`, index, refs, `origin`), registered linked worktrees resolve after the move, foreign `.gf` content is retained and reported, an unlinked-then-cloned binding finds its uncommitted work, and ambiguous identity refuses. |
| Affected observers | `tests/` rm, clone, and worktree families; conversion/troubleshooting flows. |

### P3 — compound transitions, parent-worktree operations, concurrency, interruption, recovery

| Field | Gate |
| ----- | ---- |
| Phase baseline | The P2-admitted tree. |
| Old producer/selector | Lock-free `main` dispatch — the `GF-TRB-11` last-writer-wins window — and ad-hoc partial-effect handling. |
| New producer/selector | `platform.acquire_lock`, `cli._acquire_parent_lock`, lock-bearing mutating commands; the partial-effect envelopes and provably-created-only cleanup of `GF-D21`/`GF-D22`. |
| Permitted coexistence | Read commands and passthroughs stay permanently lock-free — coexistence is the design, not a migration state. |
| Prerequisite and switch ordering | Follows P2; the lock is acquired before planning reads so no planning window races a writer. |
| Authority surviving the switch | All P1/P2 authority; `GF-TRB-11` is closed by the lock admission and stays recorded, not deleted. |
| Preservation/recovery verification | Concurrency witnesses (concurrent pulls, clone-with-rm), kill witnesses at each partial-effect boundary, recovery idempotence, and `worktree add`/`remove` rollback. |
| Affected observers | The concurrency and recovery witness families; every mutating command's tests. |
